# AI Financial Data Annotation

## Project Overview

This project demonstrates a structured methodology for annotating financial text and transactions for AI training and evaluation.

The focus is on **domain-aware labeling**: the annotator must understand accounting concepts while following explicit annotation rules, preserving source meaning, extracting values accurately, and flagging ambiguity instead of guessing.

> **Portfolio status:** Simulated self-directed annotation case study.

## Objective

Create consistent, auditable financial annotations covering:

- Financial concepts
- Transactions
- Financial entities
- Numerical values
- Business topics
- Relevance and ambiguity

## Label Taxonomy

| Label | Definition | Example |
|---|---|---|
| Revenue | Income generated from sales or services | Product sale |
| Operating Expense | Cost of normal business operations | Office rent |
| Asset | Resource controlled by the business | Equipment |
| Liability | Present obligation to another party | Bank loan |
| Equity | Residual interest after liabilities | Owner's equity |
| Inventory | Goods held for sale or production | Merchandise |
| Accounts Receivable | Amount owed by customers | Credit sale |
| Accounts Payable | Amount owed to suppliers | Supplier invoice |
| Cash Flow | Movement of cash | Customer payment |

## Annotation Output Schema

For each example, record:

1. Source text
2. Primary label
3. Subcategory when applicable
4. Financial entity
5. Numerical value and unit
6. Evidence span / supporting phrase
7. Confidence
8. Ambiguity flag
9. Annotation rationale

## Annotation Guidelines

- Read the complete statement before labeling.
- Use the most specific supported label.
- Do not infer information that is absent from the text.
- Preserve the source meaning.
- Extract numbers exactly as stated.
- Distinguish accounting classification from business-topic classification.
- Flag cases where available context is insufficient.
- Apply the same decision rule to similar examples.

## Evidence-Based Annotation Example

### Input

> "The company reported revenue of $750,000 during the financial year."

### Annotation

```text
Label: Revenue
Entity: Revenue
Value: $750,000
Evidence: "revenue of $750,000"
Confidence: High
Ambiguous: No
Rationale: The statement explicitly identifies income generated by the company as revenue.
```

## Ambiguous Case

### Input

> "The company spent $3,000 on a computer system."

### Decision

**Potential labels:** Operating Expense / Asset

The phrase does not provide enough information about capitalization policy, expected useful life, or materiality to guarantee a definitive accounting classification in every context.

**Annotation decision:** Flag for review rather than guessing.

This is important because a good annotator should know when **not** to force a label.

## Quality-Control Framework

### First Pass

Annotator applies the label and records evidence and confidence.

### Second Pass

Reviewer checks:

- Label correctness
- Numerical extraction
- Evidence span
- Consistency with guidelines
- Ambiguity handling

### Error Taxonomy

- Wrong label
- Missing label
- Incorrect value
- Missing value
- Wrong evidence span
- Unsupported inference
- Inconsistent label
- Failure to flag ambiguity

## Annotation Quality Metrics

For a larger dataset, useful quality measures include:

- Label accuracy
- Agreement rate
- Inter-annotator agreement
- Ambiguity rate
- Correction rate
- Numerical extraction accuracy
- Reviewer rejection rate

These metrics should be interpreted in the context of the annotation guidelines and task definition.
